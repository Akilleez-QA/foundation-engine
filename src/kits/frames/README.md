# Coordinate frames and delayed pose updates

Optional `frames()` kit. Local affine coordinate handling and bounded received-update application; no network transport, server authority or prediction is provided.

`createFrames(maxFrames = 128, maxDepth = 16)` stores immutable finite invertible matrices keyed by `{ id, generation }`. Parent references include generation. Missing parents resolve as null; cycles and excess depth/capacity fail. `remove(ref)` cancels that generation. A removed ID must advance generation before reuse; retained generation tombstones count toward the identity capacity, so a late update cannot revive an old visit. Reconstruct the store on whole-session teardown, not to bypass stale protection within a session.

Frame identity admission requires a nonempty primitive string and a nonnegative safe-integer generation. `frameRef`, registration, removal and resolution capture identity values before use; malformed identity admission does not consume capacity or advance a pending update sequence.

`createFrameUpdates(frames, maxOwners = 128)` requires explicit `register(id, generation)`. `offer(id, { generation, sequence, frame, local })` replaces one pending record only when its sequence exceeds `newestSeen`. `applied` advances only when `pump(workLimit)` resolves the complete parent chain. An old packet cannot overwrite newer waiting work. `cancel` clears pending/applied pose and requires a new generation on re-registration. `state` exposes newest-seen versus applied sequence, applied frame identity, world pose and pending status. Owner tombstones count toward capacity. Pump rotates examined records, including missing-parent records, so one unavailable parent cannot starve another owner. No unbounded retry queue or per-packet allocation backlog.

`FrameReplica({ owner, generation })` plus `frameReplicaSystem(updates, workLimit)` integrates applied poses into author `Transform`. Marked entities must have this as their sole pose writer; gate ordinary movement while replica-owned. Applied local poses remain attached to their generation-qualified frame. Budgeted pump refreshes world pose after parent motion without another packet; a separate revision drives the author adapter while applied packet sequence stays unchanged. If the applied parent becomes unavailable, state.world becomes null and the adapter holds the last displayed pose until explicit recovery or a valid newer frame update. Pending newer updates do not detach a still-valid applied frame. Author Transform supports uniform scale only, so shear/nonuniform scale is rejected instead of silently discarded.

Costs: O(depth) resolution, bounded identities × matrix storage; O(workLimit × depth) pump plus O(marked entities) author adapter. No draws, transport, subscriptions or timers. Parent registration/definition validation is synchronous and bounded by maxDepth. This addresses frame/sequence acceptance, not a deployed replication protocol.

The author adapter caches the owner name, generation, pose revision and native Transform identity together. Rebinding a replica or replacing its Transform applies the current resolved pose even when its numeric revision matches the previous lifetime. Replacing a parent frame generation does not retarget an existing attachment: a newer explicit update must name that generation. Headless tests cover these boundaries; they do not establish transport or runtime playability acceptance.
