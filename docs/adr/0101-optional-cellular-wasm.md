# ADR 0101: Optional cellular WASM worker kernel

- **Status:** Proposed
- **Date:** 2026-10-08
- **Area:** Procgen / Workers

## Context

A local comparative experiment found a handwritten Rust/WASM cellular kernel
worth testing through the real worker framework. That experiment did not establish
whole-engine compiler feasibility, mobile performance or production memory ownership.

## Decision

Offer an explicit alternative cellular job without changing the JavaScript default.
Reuse grid validation, WorkerHost admission and prepared-resource ownership.
Keep immutable compiled modules per worker and fresh fixed linear memory per active
job. Add a bounded, captured fixed scratch allowance to the existing generator
contract rather than creating another memory scheduler.

Keep the same seeded results and cumulative 4096-visit checkpoints. Failed worker
execution reports failure; worker-unavailable fallback and direct generation use
JavaScript. Ship reproducible generated bytes with their original Rust source and
pinned build instructions.

## Acceptance and reversal

Exact output, bounded ABI, independent instances, cancellation and byte retirement
are the acceptance surface, exercised by unit tests and actual worker browser
checks. Hosted full CI is required before integration. Physical-device speed and
thermal suitability remain separate creator acceptance.

The creator can choose the existing JavaScript job without changing the recipe
or saved seed. This backend does not require new game mechanics, a renderer change,
a Rust game language or support for every device.
