# Recipe workbench

This optional desktop authoring consumer demonstrates bounded recipe editing and isolated evaluation. Creators may replace the sample schema, ingredients and workflow. It does not prescribe a crafting economy, random minigame or universal quality score.

`tools/crafting-workbench/recipe.mjs` exports `captureRecipe`, `initialRecipe`, `initialStock`, `initialSelections`, `evaluateRecipe`, `craftBounds`, `stockBounds` and `recipeLimits`. Capture returns detached frozen semantic fields and validates references with the actual crafting evaluator. Recipe ID and version are labels: two captures with identical labels may contain different facts. Runtime adoption must retain the complete capture.

The example starts with two source containers, four units each, and distinct batches whose grade values are 400 and 800. Selecting one of each gives a quantity-weighted ceiling of 600 and an initial value of 300. The sample output has mass 18; two input units have mass 20, leaving two units of mass-one scrap. These numbers are authored example content. The evaluator uses integer slot means, recipe weights, initial/gain/effect permille and bounded affine output terms; intermediate rounding matters.

`createEditorController({saveHandle, readPersisted, saveBuild})` owns one existing authored document and edit session. `preview(recipe)` stages a candidate and evaluates it without stock writes, reservations or point spending. A semantically valid recipe incompatible with the sample preview ingredients remains editable: `read().evaluation.status` reports `incompatible`. Invalid schema removes the prior preview and leaves the accepted recipe intact. `commit`, `cancel`, `undo`, `redo`, `startPreview` and `stopPreview` are explicit. Runtime sessions must capture `read().recipe`; editor undo cannot revoke manufactured outputs or change an adopted recipe.

Authoring history admits 16 entries and 512 KiB. Recipe intake admits 131,072 UTF-8 bytes, 16,384 nodes and depth 24. The sample bounds are four slots, eight selection rows, four attributes, sixteen weights per attribute, eight steps, sixteen points and eight output properties. These are joint ceilings, not promises that every maximum combination fits the document or stock. Stock admits 32 containers, 16 retained batches, 64 positions, 32 changes and eight properties. A factory or session must validate its actual selection and conservation separately; successful schema capture is not material availability or output acceptance.

The recipe save section is `crafting.recipe` in namespace `crafting-workbench`. Supply the actual SaveStore build string for full-envelope preflight, and wrap its storage port using `createRecipeStoragePort` before creating the store. Compose other independently scoped guards when the same store hosts runtime state. The author adapter uses mutation callbacks; returning a replacement from its update callback does not replace the draft.

`save()` reports durable only when saved status and actual versioned physical data match the accepted recipe. Fresh absent storage is explicitly non-durable. Quarantined, newer, unavailable or conflicting data blocks edits pending recovery. The key-scoped guard also protects automatic flush and disposal against observed external replacement; it is a single-writer example, not cross-process atomic compare-and-swap. Authoring and runtime sections are independently written and have no joint transaction promise.

Focused verification uses `node --import tsx --test tools/crafting-workbench/editor-controller.test.mjs`. These tests cover evaluator output and detached stock, raw UTF-8 admission, rejected/incompatible preview, actual author-save adapter, undo/reload, corruption, write retry, automatic-flush conflict protection and retirement during capture. Native UI, integrated crafting lifecycle, browser evidence and physical-device acceptance are separate requirements; this guide does not claim them from schema tests.

The recipe storage guard checks the raw envelope byte limit before returning data to SaveStore, so oversized input never reaches its recipe parser. Observed size or external-byte conflicts remain latched through automatic retries and disposal, including when external bytes later return to their earlier value. Save preflight includes the full wrapper in both UTF-16 character and UTF-8 byte limits.
