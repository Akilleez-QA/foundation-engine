# Optional cellular WASM workers

Creators can explicitly select a Rust/WASM smoothing kernel for the existing
cellular grid recipe. The normal `prepareCellularGrid` remains JavaScript.
This is a small independently implemented kernel, not a TypeScript-to-Rust
compiler or a migration of game logic.

## Use and contract

Import `prepareCellularGridWasm` from `@kits/procgen` wherever the existing
`prepareCellularGrid` is used. Its arguments and result are identical:
worker host, owner signal, recipe, request signal, and optional urgency/key.
It accepts the existing dimensions, uint32 seed and
`[fill, steps, birth, survive]` parameters, and returns the same owned
`Uint16Array` grid through the existing prepared-resource protocol.

The registered row is `job.kits.procgen.cellular-wasm`. Its default grid limit,
recipe validation, output validation, queue admission, supersession and publication
all reuse `createGridGenerationJob` and WorkerHost. No additional scheduler or
worker pool is created. A creator can continue using JavaScript, choose this job,
or supply a different generator.

The kernel handles Moore-8 smoothing only. Seeded filling and publication stay in
TypeScript. Output must match the JavaScript implementation exactly, including
outside-as-solid edges, independent per-layer random streams and all threshold
values. The guard is exact grid equality, not a visual tolerance.

## Ownership and memory

Each active job owns a fresh WebAssembly instance and fixed-size imported memory.
An immutable compiled module can be shared within a worker; mutable scratch cannot.
Two byte planes start at byte 65536. The memory page count is
`ceil((65536 + 2 * cellsX * cellsZ) / 65536)`, with maximum equal to initial:
the kernel cannot grow memory. There is no allocator or retained scratch pool.

The generic generator contract now permits `scratchFixedBytes`, captured when the
job is registered: an integer from zero through 64 MiB, default zero. This job
charges 131072 fixed bytes plus the existing two scratch bytes per grid cell,
in addition to the normal grid/output/request allowances. This conservatively
covers the kernel's stack and page rounding; using total grid cells for the two
planes over-reserves multilayer jobs. JavaScript fallback keeps the same admission
charge so route selection cannot evade admission.

WorkerHost reservations bound declared buffers, not total browser memory.
Compiled code, JIT metadata and garbage awaiting collection are not exact byte
charges. Retiring a job drops its instance/memory references; physical release is
controlled by the browser's collector. Shared compiled code lasts with its worker.

## Cancellation, failures and fallback

Filling and smoothing preserve the JavaScript generator's cumulative yield after
every 4096 cell visits, including across steps and layers. Worker checkpoints yield
to the task queue so cancellation can be observed. This is a work bound, not a
wall-clock latency promise. Compilation itself is asynchronous and cancellation is
checked before generation starts; an unresponsive worker remains subject to the
host's existing cancellation deadline.

Unavailable workers use the bounded JavaScript fallback. Direct `generateNow`
also uses JavaScript. A running worker's WASM compile/instantiate/trap failure is an
explicit failed execution, not a silent switch of backend. Failed compilation is
not cached permanently: a later request may retry. Invalid, cancelled, stale or
failed work cannot publish a partial grid. Creators may explicitly retry through
the existing JavaScript job if that recovery policy suits their application.

## Build and verification

Normal consumers require no Rust installation: generated bytes are checked in.
Source, pinned compiler, ABI, hashes and reproduction instructions are in
[the kernel tooling](../../tools/cellular-wasm/README.md).

Automated checks:

- `src/kits/procgen/cellular-wasm.test.ts`: exact output and lifetime checks.
- `src/kits/procgen/grid-job.test.ts`: fixed reservation validation and admission.
- `node --test tools/cellular-wasm/kernel.test.mjs`: binary ABI and bounds.
- `node scripts/play/cellular-wasm-check.mjs`: actual browser worker concurrency,
  JS fallback, cancellation/recovery, supersession, owner loss and byte retirement.
  Included in `npm run test:framework-browser`, which hosted CI runs.

A preceding local experiment motivated this option, but its timing does not prove
this production wrapper is faster on every device. Physical phone/tablet testing,
sustained thermal performance and application-specific timing remain unverified.
Selecting this backend does not change a game's supported-device declaration.
