# Industrial state candidates

Creator requirement: finite extraction, cargo handling, multiple product/waste outputs and player-constructed expansion must operate against the same stock. `industry.ts` composes the dimensional stock reducer into one serializable candidate containing deposits, accepted plans and machines. It creates no timer, renderer, persistence store or second stock owner. Existing production/materialization APIs remain unchanged.

The enclosing world owns command IDs/revisions/idempotency, authorizes extraction based on survey/tool/time, locks authored plans after experimentation, checks construction bills and placement, allocates finite electrical supply, and publishes the complete character/economy/home envelope only after durable acknowledgement. The low-level command is not directly safe to expose as a player-authored payload: a caller cannot invent a construction bill, select arbitrary extraction quantity or register an unapproved recipe. Those application-level contracts remain required.

Deposits have body/region and immutable batch identity with finite integer remaining units. Harvest transfers accepted quantity from reserve to stock atomically. Transfers preserve exact batch and reject private work/installed storage. Construct transfers its supplied, previously authorized bill into installed custody while adding four distinct bounded containers and a machine. Thus installed hardware continues contributing mass and cannot be counted as loose cargo or vanish from accounting.

Accepted plans name exact input batches, immutable output batches, integer work joules and maximum operating watts. Validation requires equal input/output mass, including declared residue streams. Equal mass does not establish chemically valid conversion; the authored recipe/experiment authority must verify material families, composition and allowed products. Restore validates references, bounds, output identity conflicts and active work custody. Catalogue-version migration and plan retirement are not yet supplied by this candidate layer.

At cycle admission all required input moves to private work storage in the same stock state. External cargo commands cannot spend it. Progress is integer joules with a tenths-of-joule remainder for 100 ms ticks. Results distinguish useful `workJ` from exact supplied `energyDeciJ`; the power ledger debits the latter, including sub-joule work later discarded by cancellation. Loss of power preserves partial work and earns nothing. Completion consumes work stock and emits every product together. Full output retains completed work and all reserved material; retry uses no extra process work and can publish passively during blackout. Cancellation returns original batches if input storage has capacity, otherwise changes nothing. Expended process energy is not refunded.

Each step is bounded by configured ticks and completes at most one cycle. `elapsedTicks` reports the settled portion of the requested interval; unused ticks remain with the enclosing chronological scheduler. A completed-but-blocked output consumes no additional energy while blocked. When output becomes available it can commit at zero elapsed ticks; the caller still bounds transitions independently of elapsed time to avoid unbounded catchup. Expected stock-validation failures are normalized into command result failures; programmer/accessor exceptions still propagate. Plan admission checks that reservation and completion can fit the configured operation bound. Maximum operating power is a cap, not an assertion that a network supplied that power.

The enclosing world must settle machine work to a command's effective time before changing power, transferring goods or applying capability effects. It must combine the reported energy draw with its own power/thermal budgets atomically. Offscreen/reload scheduling, global allocation across machines, compatible pipe networks, batch-reference reclamation, dynamic plan admission and scene construction readiness remain subsequent integration requirements.

Evidence: industry.test.ts composes finite harvesting, vehicle custody, installed construction stock, partial work/reload/power loss, private work protection, multiple outputs, full-output stop/retry, cancellation rollback, fractional energy, malformed restoration and expansion using manufactured parts. These are model tests, not the interactive application workflow, persistent command idempotency, calibrated chemistry or device acceptance.
