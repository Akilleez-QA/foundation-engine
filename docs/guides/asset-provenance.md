# Asset provenance and AI disclosure

Every model, texture and sound a game ships has a **provenance record**: who made it, how, with which tool and model, under which licence, from which prompt or reference, what a person changed afterwards, and the file's hash. `npm run check` reports files without one. `npm run disclosure` turns the records into draft text for the Steam and itch.io AI-disclosure forms.

Status: implemented and checked (focused tests; see [the ledger](upgrade-acceptance-ledger.md), DX-03). The records are receipts the creator writes, not proof of rights. Nothing here decides whether a licence claim is true or whether a store will accept the text.

## Where records live

Either beside the file, or in one file for the game. Each shipped file has exactly one record.

| Where | For | Example |
|---|---|---|
| `<public>/<dir>/<name>.provenance.json` | any file, and the receipt a model export already writes ([Blender export sample](../../tools/blender-export/README.md)) | `game/public/models/lantern.glb` → `game/public/models/lantern.provenance.json` |
| `game/assets.provenance.json`, under `assets`, keyed by the path inside `public/` | many small files (sounds, textures) | `"sounds/jump.ogg": { … }` |

A record beside the file may name it in `artifact`. When two files share a name with different extensions (`wood.png`, `wood.webp`), the sidecar belongs to the one its `artifact` names; give the other an entry in `assets.provenance.json`.

Checked kinds: models (`.glb`, `.gltf`), textures and images (`.png`, `.jpg`, `.jpeg`, `.webp`, `.avif`, `.ktx2`, `.hdr`, `.exr`) and sounds (`.ogg`, `.oga`, `.opus`, `.mp3`, `.wav`, `.m4a`, `.aac`, `.flac`, `.weba`). Decoders, JSON data and the records themselves are not.

## Record fields

| Field | Required | Meaning |
|---|---|---|
| `origin` | always | `hand` (a person made it, by hand or with a script they wrote), `agent-blender` (an AI agent built it by driving Blender, for example through the Blender MCP server and the [blender-asset skill](../../.claude/skills/blender-asset/SKILL.md)), `ai-generator` (an AI model or service generated it: 3D, image, texture, sound, voice), `library` (taken from a library or another author) |
| `author` | always | Who made it; for a library asset, the original author as its licence asks to be credited |
| `licence` | always | The asset's own licence, SPDX where one exists (`CC0-1.0`, `CC-BY-4.0`, `GPL-3.0-only`) |
| `source` | always | The script that made it, the library page, or the generator job |
| `sha256` | always | The shipped file's SHA-256, lowercase hex. `npm run check` recomputes it |
| `tool` | `agent-blender`, `ai-generator` | Tool and version: `Blender 5.2.1 LTS + Blender Lab MCP 1.0.3`, `Tripo v3.1 (web, Pro plan)` |
| `model` | `agent-blender`, `ai-generator` | The AI model and version that made it: the agent's model, or the generator's |
| `weightsLicence` | `ai-generator` | Licence of the generator's weights, or `proprietary service` |
| `outputLicence` | `ai-generator` | The terms the output is under, from the generator's terms for your plan |
| `prompt` or `reference` | one, for `agent-blender` and `ai-generator` | The prompt, or the image, sketch or model it was made from |
| `humanEdits` | `agent-blender`, `ai-generator` | What a person changed afterwards, or `none` |
| `artifact` | no | The file name, for a record beside the file |

Other keys are kept and not checked here, so a model receipt's bounds, `generator` or `sourceSha256` can share the file.

```json
{
  "origin": "agent-blender",
  "author": "Sam Rivera",
  "licence": "CC0-1.0",
  "source": "game/tools/lantern/build.py",
  "tool": "Blender 5.2.1 LTS + Blender Lab MCP 1.0.3",
  "model": "Claude Opus 5.5",
  "reference": "docs/ref/lantern-front.png (front view, own photo)",
  "humanEdits": "glass colour retuned by hand",
  "artifact": "lantern.glb",
  "sha256": "…"
}
```

## The game file

`game/assets.provenance.json` (optional, but the disclosure stays incomplete without it):

```json
{
  "schema": 1,
  "tooling": [{"use": "code", "tool": "Claude Code", "model": "Claude Opus 5.5"}],
  "liveGenerated": false,
  "assets": {}
}
```

- `tooling`: AI help that is not a shipped file. `code` (agents and code assistants) and `other` (tests, planning, reviews) are development tooling, which players never see. `text` means player-facing words (strings, dialogue, lesson text) were written or drafted with AI, so it is disclosed as content. An empty list states that none was used.
- `liveGenerated`: `false` when nothing is generated by AI while the game runs, or a description of what is and its guardrails.

## The check

`npm run check` runs `lint:provenance` on the active game. Each shipped file without a valid record, a record with missing fields, a hash that does not match, two records for one file, or an entry for a file that does not exist is a **warning** by default: the check passes and prints it. A brief can make them errors:

```ts
defineBuild({ …, assets: { provenance: 'required' } });
```

Changing that is a brief change: record it in GAME.md's changelog.

## The disclosure draft

```sh
npm run disclosure                       # Markdown for the active game
npm run disclosure -- --game <dir> --json
npm run disclosure -- --strict           # exit 1 when the draft is incomplete
```

The draft has:

- **Steam** (the AI generated content disclosure on the store page): *pre-generated* content (AI-made files players see or hear, and player-facing text written with AI), *live-generated* content (from `liveGenerated`), and, separately, the development tooling, which Steam's form says it does not cover.
- **itch.io** (the AI generation disclosure): Graphics, Sound, Text & Dialog and Code, each Yes, No or Unknown with its basis. Graphics and Sound come from the shipped files; Text & Dialog and Code from `tooling`.
- The list of AI-made files with tool, model and human edits, and the gaps.

A file without a valid record makes the draft **INCOMPLETE**, and the categories it could affect say Unknown, never No. Both `agent-blender` and `ai-generator` files count as AI-made content: an asset an agent built in Blender is disclosed, with its human edits. Review the draft and paste it yourself; the command publishes nothing. Store rules change: check the current form wording before you submit.

## Owner, bounds and limits

- **Owner:** the creator writes the records; `scripts/lib/provenance.ts` only reads. `npm run check` and `npm run disclosure` are its callers. It is not a runtime check and does not run in the browser.
- **Bounds:** one listing of the public folder and one SHA-256 per checked file. Nothing is fetched.
- **Failure:** an unreadable or malformed record is reported for its file; the other files are still checked.
- **Not established:** whether a licence or authorship claim is true, whether a generator's terms allow the use, whether the store accepts the wording, and the provenance of files outside `public/` (code, strings) beyond what `tooling` declares. `defineAsset`'s `licence`, `author` and `source` are not yet cross-checked against the records. Model geometry and budgets are checked by model contracts and `npm run asset:verify` where those exist, not here.
