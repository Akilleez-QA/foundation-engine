# Custody composition diagnostic

This optional desktop keyboard/pointer example demonstrates one coherent accepted envelope across unique-instance world placement, local equipment custody, material reservations and production settlement. The finite identities, single equipment slot, positions and bag capacity belong to the example, not engine game-design policy. It does not claim multiplayer authority, nested containers, phone/tablet certification or physical-device timing acceptance.

The existing controller composes the equipment, inventory, materialization, authored-document and SaveStore seams. The UI owns only native controls and a bounded Shape projection. Every visible unique shape derives from the controller's accepted envelope; SaveStore's dirty candidate is never treated as accepted presentation. All candidate validation happens before external publication. Once publication is attempted, cancellation is refused: only the exact snapshot may retry or acknowledge matching durable bytes.

The full viewport stays available until the user opens the reading sheet. The sheet uses existing layer/focus ownership, returns focus on close and retires listeners with its scene. Closing the sheet discards only an unattempted candidate; it cannot promise to cancel pending storage publication. Failed capacity, stale/cancelled actions and duplicate requests must preserve the accepted locations. Reload distinguishes old durable state from a candidate that became durable during teardown.

Run `node scripts/play/custody-composition-check.mjs` for the muted browser diagnostic. Evidence defaults to `playtest/custody-composition`. Browser results remain unverified until a run passes on the final integrated head. Controller tests separately exercise corrupted envelope coherence and lifetime/capture boundaries; a browser screenshot alone is not proof of those invariants.

Successful acknowledgement closes the reading sheet so the resumed scene renders its newly accepted Shapes. The browser waits for an actual render-counter advance for changed projections before taking world screenshots. Pure metadata publications do not force an unnecessary redraw. The independent oracle enumerates every named ECS entity and checks its Shape and Transform against the accepted envelope; it does not trust the projection's private cache. The explicit competing-revision diagnostic retains its old preview while closing for publication so the subsequent stale-ticket refusal can be exercised; ordinary user closure discards unattempted previews.
